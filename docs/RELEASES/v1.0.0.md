# v1.0.0

## Summary

ScriptPlayground 1.0.0 is a local Discord bot development playground that runs real multi-file Python `discord.py` and Node `discord.js` projects offline against a simulated Discord server, alongside the existing single-file editor, interaction simulator, inspectors, and scenario runner. It also ships as an optional Windows desktop application with persistent user data.

## What's in it

### Runtime fidelity

- Boot complete Python bot workspaces through `discord.py`'s login and setup lifecycle with a fake REST/webhook transport; cogs, command sync, ready handlers, slash commands, component interactions, modals, and message handlers run against the local simulator without Discord gateway or REST traffic.
- Run Node `discord.js` workspaces using a bundled shim and stdio bridge; no `npm install` is needed, but Node must be on `PATH`.
- Redirect project entry points that call `asyncio.run(bot.start(...))` onto the simulator loop, and replace bot-token values in the runtime copy with an offline placeholder.

### Desktop launcher

- Add a Python desktop launcher and a Windows one-folder executable build with an app icon, browser app-mode launch, and graceful shutdown behavior.
- Keep packaged scripts, bot workspaces, scenarios, and designs in persistent user data (`%LOCALAPPDATA%\ScriptPlayground` on Windows); support `--data-dir` and `SCRIPTPLAYGROUND_DATA_DIR` overrides and seed defaults without overwriting user files.

### Environment discovery

- Add an Env inspector for `.env`, `.env.example`, `.env.local`, `.env.development`, and `.env.production`, showing declared/provided variables and missing example-schema entries while redacting secret-looking values.

### Inspectors

- Make runtime event/action details traceable to related events and messages, expose startup and callback errors with available source locations, and improve the Discord-like shell with an informational member rail, channel header context, incremental timeline updates, and reduced-motion support.

### Scenarios

- Add version-1 JSON scenarios that save and replay message, component-click, modal-submit, and slash-command steps against a running session, with assertions for messages, embeds, components, channels, and events.

## Known limitations

- No real gateway events or simulator REST requests. OAuth's identity request is the deliberate exception: it calls Discord only during an explicitly configured sign-in callback, never from simulator operations.
- No permission-management UI.
- No multi-guild state.
- No voice or stage model.
- No threads, DMs, webhooks, forums, scheduled events, rate limits, or intent simulation.
- OAuth sessions are memory-only, do not survive restart, and do not provide guild discovery, account settings, real Discord data access, or real Discord actions. Callback-query redaction is guaranteed by the production `web.run_app()` wiring, not by arbitrary embedding callers that choose aiohttp's default access logger.
- Some mock methods are intentionally shallow and may accept arguments that real Discord would reject.
